Concurrency: an introduction

A thread is another point of execution inside a single process: its own program counter, its own registers and its own stack, but the same address space as every other thread in the program. The tabs below follow OSTEP Chapter 26, from what a second stack looks like to why a shared counter ends up with the wrong value.

Private and shared

          

          
The OS keeps one thread control block per thread, much as it keeps a process control block per process. Switching between threads of the same process leaves the address space, and so the page table, untouched.

void *mythread(void *arg) {
    printf("%s\n", (char *) arg);
    return NULL;
}

int main(int argc, char *argv[]) {
    pthread_t p1, p2;
    printf("main: begin\n");
    Pthread_create(&p1, NULL, mythread, "A");
    Pthread_create(&p2, NULL, mythread, "B");
    // join waits for the threads to finish
    Pthread_join(p1, NULL);
    Pthread_join(p2, NULL);
    printf("main: end\n");
    return 0;
}

Shared memory

          
One counter at address 0x8049a1c, reachable by both threads because they share the address space.

The words for it

          
A critical section is a piece of code that touches a shared resource, here the three instructions that update the counter.

          
A race condition is when the result depends on when the scheduler happens to switch. The outcome is indeterminate: correct on most runs, wrong on some.

          
The fix is mutual exclusion, a guarantee that only one thread is inside the critical section at a time, so the update becomes atomic. That is what locks are for, and is where the next chapters go.
