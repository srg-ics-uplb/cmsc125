Locks and condition variables

A lock is the restroom: one key, one room, and whoever holds the key is inside. A condition variable is the waiting room next door, with a bell: a thread sleeps there until another thread rings to say that what it was waiting for has happened. The tabs follow OSTEP Chapter 28 (Locks) and Chapter 30 (Condition Variables).

The words for it

          
A lock gives mutual exclusion: while one thread is in the critical section, the others are kept out.

          
To build one, the check and the set must be atomic, one step the scheduler cannot split. Test-and-set is a hardware instruction that does exactly that.

          
A spin lock waits by looping. It is simple, and fine for very short critical sections on several CPUs. On one CPU it is wasteful, because the spinner holds the CPU that the lock holder needs.

          
A sleeping lock parks the waiter in a queue and wakes it with unpark. The next tab is about the same idea used for a different job.
